# Simian Radar Phase 1b (all-signals modes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add the 13 new scanner modes from the modes design so the device has 16 button-cycled modes covering everything its 2.4 GHz, 900 MHz and GPS receivers can hear.

**Architecture:** Same split as Phase 1: every parser and detector is pure C++ in `lib/` with host tests (`tools/native_test.sh`); thin device adapters in `src/hw/`; screens in `src/ui/`. The WiFi sniffer callback only copies a small header record into a FreeRTOS queue; all classification runs in `loop()`. The SX1262 is driven through RadioLib and is only ever put in standby, receive, CAD or RSSI reads.

**Tech Stack:** as Phase 1, plus `jgromes/RadioLib@^7` and vendored opendroneid-core-c (Apache-2.0) for Remote ID.

**Spec:** `docs/2026-10-31-simian-radar-modes-design.md` (and the base design it extends).

## Global Constraints

- All Phase 1 constraints hold (pins in `lib/config/Config.h`, Vext active LOW, GPS UART ESP RX=39/TX=38, no em dashes on screen, no AI attribution in commits).
- **No transmit path may exist.** No call to any RadioLib `transmit`/`startTransmit`/`scanChannel`-with-TX or WiFi connect/inject API. Verified by grep in Task 20.
- SX1262 pins: NSS 8, SCK 9, MOSI 10, MISO 11, RST 12, BUSY 13, DIO1 14, TCXO 1.8 V, DIO2 as RF switch. FEM: power LDO pin 7 HIGH, GC1109 enable pin 2 HIGH, PA mode pin 46 LOW (bypass, receive). Values from MeshCore `variants/heltec_v4`.
- Mode order and tags exactly as the modes design table.
- 900 MHz modes run only while on screen; SX1262 to standby when leaving.
- Meshtastic is GPL-3.0: take only published facts (frequencies, header layout), no code.

## Review Focus

1. Malformed or truncated frames/packets (short lengths, bogus IE lengths) must never read out of bounds. Each parser task has `test_truncated_*` tests.
2. Busy places (hundreds of phones/BLE adverts per second) must not grow memory: every table is fixed-size with LRU eviction. Tests `test_*_caps`.
3. Leaving a 900 MHz mode mid-receive must leave the radio in standby, and re-entering must restart cleanly (board check in Task 20).
4. Remote ID packs with unknown message types or counts larger than the buffer are skipped, not crashed on (Task 16 tests).
5. Attack detector must not flag ordinary busy networks (a mesh WiFi system with many BSSIDs for one SSID from one maker is not an evil twin). Test in Task 15.
